# Design

## Context
订单簿包含协议版本、资产标识、tick_size 和 min_order_size。旧客户端只支持部分价格增量，不能假定任意增量可被旧客户端签名。

## Goals / Non-Goals
**Goals:** 不改变用户提交的限价或份额，使用实时订单簿进行精确校验。
**Non-Goals:** 不更改钱包或授权流程，也不保证交易所在请求期间规则不会变化。

## Decisions
以 Decimal 校验价格为 tick 的整数倍且在 tick 至 1-tick 范围内，校验份额为两位小数且达到市场最低值。直接输入不合法时拒绝；由金额或百分比计算的数量在提交前明确向下取整。模拟模式使用相同校验。对于旧 SDK 无法支持的价格增量，返回明确错误，避免签名失败或错误。

## Risks / Trade-offs
[市场规则变化] → 每次提交重新读取订单簿，服务器仍是最终裁决者。 [浮点运算] → 使用十进制字符串转换和 Decimal 校验。
