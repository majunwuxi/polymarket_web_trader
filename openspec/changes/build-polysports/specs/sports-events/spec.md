# Spec Delta

## Purpose
将足球和 NBA 比赛统一持久化并支持赛事关注与可恢复的完赛查询，同时保留外部数据来源、时间和身份的可核验性。

## ADDED Requirements

### Requirement: 赛程同步和展示
系统 SHALL 使用 API-Football 和 BallDontLie 分别同步未来 36 小时赛程，默认每天 UTC 00:00 与 08:00 运行且允许修改，并通过稳定来源标识避免重复，保留历史记录。系统 SHALL 分设足球和 NBA 赛事中心并展示队徽、中文名与 UTC+8 时间；无法确认译名时明确标记待补充。

#### Scenario: 重复同步
- **WHEN** 同一来源赛事被再次同步
- **THEN** 系统更新已有记录且不产生重复赛事

#### Scenario: 缺失球队译名
- **WHEN** 无法验证球队中文译名
- **THEN** 系统显示来源原名并标记待补充，不虚构中文名

### Requirement: 持久关注与赛果查询
系统 SHALL 将发起订单的相关赛事设为关注；足球首次查询时间为开赛后 120 分钟，NBA 为 159 分钟，此后分别每 10 分钟和 3 分钟查询，确认完赛后停止常规查询。

#### Scenario: 服务器重启
- **WHEN** 服务重启并恢复关注任务
- **THEN** 系统根据持久化截止时间恢复调度，不提前执行尚未到期的任务

#### Scenario: 完赛确认
- **WHEN** 数据源确认比赛完赛
- **THEN** 系统记录赛果并停止该比赛的常规轮询

### Requirement: 赛事来源的完整性和历史
系统 SHALL 对 API-Football 和 BallDontLie 使用各自官方协议获取未来 36 小时数据，校验所有分页和必要字段；分页失败或字段不完整时记录失败，不得冒充完整成功。按来源与外部 ID 去重，保留赛事状态、时间、比分变更历史，并允许管理员维护经过确认的中文名和别名。

#### Scenario: 后续页失败
- **WHEN** 来源后续分页失败或返回无效分页信息
- **THEN** 同步标记失败或部分完成，不报告完整成功，也不编造赛事

#### Scenario: 赛事被更正
- **WHEN** 已保存赛事的开赛时间、状态或比分发生变化
- **THEN** 原赛事保持唯一，系统追加变更记录

#### Scenario: 球队信息缺失
- **WHEN** 中文名或队徽未得到确认
- **THEN** 赛事中心显示原名和待补充状态，并使用缺失占位

#### Scenario: 来源时间跨日期
- **WHEN** 按来源日期查询跨越 UTC 日期边界的 36 小时窗口
- **THEN** 在本地精确过滤窗口内的 UTC 开赛时间并显示为 UTC+8
