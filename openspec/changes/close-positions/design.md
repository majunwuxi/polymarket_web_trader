# Design

## Context
单场订单保存历史成交量，资产余额属于钱包而非某一笔订单。组合历史记录保存各腿但未保存组合持仓 position ID。现有单场下单只发送 GTC 限价单，组合通过 Requester 报价交易。

## Goals / Non-Goals
单场与组合支持在实时余额、盘口与明确授权下进行退出；不使用历史数量冒充当前持仓，不发送重复请求或自动实际交易。

## Decisions
单场必须从订单查到原钱包、原资产并实时读取可卖余额和流动性，显示份额、价格限制与真实资金确认。用户选择 FOK（全部成交或不成交），不得将提交等同成交。组合使用原组合腿构造 SELL RFQ，核验返回的组合持仓身份和实时余额，清晰展示报价后确认。历史记录缺失组合资产标识时需从官方来源可靠恢复，否则明确不可操作，不能猜测。用户确认后服务端持久化唯一操作意图，失败或未知状态保留并只读对账，重启不可重发。卖出交易独立记录并能追溯到原始记录；同资产多笔买单共享钱包持仓时必须说明份额归属。

新组合 RFQ 的响应中包含服务端验证的 YES position ID，在报价校验后持久保存，为后续链上余额核验提供身份；历史组合保留空值，不能推断或回填虚构数据。

历史组合先根据已保存的原始腿向官方请求 SELL 报价，再读取原交易在 Polygon 上的成功回执；只接受官方 PositionManager ERC-1155 转入原钱包且资产编号与 SELL 报价一致的记录，核验转入数量足够后记录该编号。无法验证回执时不允许接受报价。最终接受前仍检查实时余额和授权。

## Risks / Trade-offs
交易所价格、余额、授权及可用深度会变化；无法保证成交。测试仅使用明确标记的模拟数据，不发送真实订单。
