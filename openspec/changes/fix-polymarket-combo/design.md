# Design

## Context
赛事选项已由 Polymarket gameId 和市场身份核验，组合市场还必须经官方目录验证专用 position ID。既有接受流程有持久化、幂等和单次发送保护。

## Goals / Non-Goals
支持从赛事中心选取多个可组合选项并询价；不猜测报价、成交或钱包权限，不自动提交真实订单。

## Decisions
选择选项后先通过既有市场身份接口，再检查组合目录，成功才加入本机组合单；提交询价及接受报价前仍重新核验。保留 Builder Gateway 和显式启用开关。接受报价后仅在官方状态确认成功时持久化启动赛事结果绑定；未知、拒绝、执行中不声称成交，不自动重发。旧来源赛事继续沿用既有关注行为。

个人账户不应被强制要求 Builder 凭证。官方 Requester Gateway 使用 CLOB L2 认证、独立请求路径及零 Builder attribution；当前固定版本 SDK 的高级组合方法只支持 Builder Gateway，需实现并测试个人 Requester 传输、签名、响应解析、仅一次接受和原 RFQ 对账，不能只移除凭证检查。

报价截止时间短：界面显示剩余时间，过期时禁用接受；提交时展示进度，对明确的发送前校验错误显示安全原因，并刷新记录。网络异常或服务器未知错误可能已发送，须在本机屏蔽重复接受并提示查看记录，不能将它当作未发送。后端在外部目录检查之前检查内存报价的有效性，保留发送前最终核验。

询价接口已返回完整报价，页面直接使用该响应在询价表单旁显示可核对的赛事、价格及确认按钮，不等待另一次钱包和记录请求。后台过期任务按报价真实到期时间安排，避免报价到期后长时间阻塞后续询价；不能自动接受或放宽现有资金和身份校验。

交易记录现有接口只包含单场订单。页面增加独立组合区，从现有组合 RFQ 只读接口分页获取，明确标记组合类型、状态及各腿；展示报价时标明为报价，不伪造实际成交费用、盈亏或结算。两个列表各自处理加载失败与分页。

成交记录通过组合接口的服务端 confirmed 条件筛选后再分页，其他询价状态仍保留在组合记录。确认组合时原流程已调用幂等的关注与绑定创建；逐腿返回关注状态、绑定状态、比分和下一次任务时间以便核查，外部绑定未完成时不得声称比分验证成功。

历史 RFQ 属于 Builder 网关。迁移时标记历史记录的网关类型，新请求明确标记为 Requester；恢复任务按照记录的类型查询，不能跨网关误判。

组合市场目录数据可能超过既有页数上限，逐页遍历会使所有选择失败。改为通过官方 SDK 按市场 ID 获取单条 Gamma 市场详情，要求 `comboStatus` 为 `enabled` 且市场有效，并逐项核对 condition ID、市场 ID、选项标签及 position ID。不能获得完整明确证据时拒绝，不使用 CLOB token 替代 position ID。

## Risks / Trade-offs
官方目录、Builder 权限、报价和资金可能不可用，须展示具体原因；报价有有效期，不得用显示的单场价格估算组合成交。自动化测试只用模拟数据。
