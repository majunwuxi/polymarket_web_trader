# Design

## Context
Polymarket Gamma 按足球标签提供比赛事件、球队、开始时间和不同市场类型。一次比赛可有多个事件；必须按 `gameId` 等经过验证的标识聚合，不得把半场、让分或准确比分当作胜平负。

## Goals / Non-Goals
展示未来 36 小时内 Polymarket 上符合足球范围的胜平负赛事以及 NBA 比赛；保留既有 NBA 和历史。API-Football 和 BallDontLie 分别用于订单确认后的足球和 NBA 赛果核验。

## Decisions
先独立实现和测试发现适配器，再处理迁移、调度及接口。Gamma 事件分页不可截断，使用来源明确的比赛编号、主客队和开赛时间，本地过滤窗口。编号缺失或不一致的上游记录不得猜测为另一场比赛。下单前核实 Polymarket 赛事和市场身份，但不要求外部赛果源绑定。仅当上游明确接受订单并能确认订单身份后，持久化赛果绑定任务；超时、拒绝和结果未知不得触发绑定，未知订单先对账。接受订单不等于成交。持久化时维持赛事来源身份和已确认的外部绑定，禁止猜测或覆盖历史。绑定采用候选证据及人工确认。按既定延迟查询外部赛果并确认完赛，订单输赢须结合市场规则及实际成交核实；无法判断时保持待核实。未绑定或来源失败时不能虚构比分或完赛；既有交易保护不得削弱。

赛事详情可直接选择来源选项；后台按所选赛事、事件、市场和选项重新核验并记录映射，订单预览仍检查盘口和资金。购买金额按限价换算份额并向下取两位小数，具体成交和费用由交易所确认。

赛事市场只接受明确的 `sportsMarketType` 值 `moneyline`、`spreads`、`totals`，并按类别跨事件分组；其他类型和无法确认的类型不展示。相同标签的市场仍保留来源事件和市场标识供下单核验。

## Risks / Trade-offs
Polymarket 仅覆盖其开设市场的赛事；来源字段缺失或矛盾时跳过并记录。来源分页不完整时同步失败。API-Football 免费权限可能无法绑定当前赛事，必须明确报告。真实交易和有密钥联调不在自动化测试中执行。
