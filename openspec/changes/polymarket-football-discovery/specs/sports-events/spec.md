# Spec Delta

## MODIFIED Requirements

### Requirement: 赛程同步和展示
系统 SHALL 使用 Polymarket 足球胜平负市场和 BallDontLie NBA 接口分别同步未来 36 小时赛事，默认每天 UTC 00:00 与 08:00 运行且允许修改，并通过稳定来源标识避免重复，保留历史记录。系统 SHALL 分设足球和 NBA 赛事中心并展示来源可验证的队徽、中文名与 UTC+8 时间；无法确认译名时明确标记待补充。

#### Scenario: 重复同步
- **WHEN** 同一来源赛事被再次同步
- **THEN** 系统更新已有记录且不产生重复赛事

#### Scenario: 缺失球队译名
- **WHEN** 无法验证球队中文译名
- **THEN** 系统显示来源原名并标记待补充，不虚构中文名

#### Scenario: 非胜平负市场
- **WHEN** 足球事件只有半场、让分或其他非胜平负市场
- **THEN** 系统不将其作为符合条件的足球胜平负赛事

### Requirement: 赛事来源的完整性和历史
系统 SHALL 对 Polymarket 足球市场和 BallDontLie NBA 使用各自官方协议获取未来 36 小时数据，校验所有分页和必要字段；分页失败或字段不完整时记录失败，不得冒充完整成功。按来源与外部 ID 去重，保留赛事状态、时间、比分变更历史，并允许管理员维护经过确认的中文名和别名。

#### Scenario: 后续页失败
- **WHEN** 来源后续分页失败或返回无效分页信息
- **THEN** 同步标记失败或部分完成，不报告完整成功，也不编造赛事

#### Scenario: 赛事被更正
- **WHEN** 已保存赛事的开赛时间、状态或比分发生变化
- **THEN** 原赛事保持唯一，系统追加变更记录

#### Scenario: 球队信息缺失
- **WHEN** 中文名或队徽未得到确认
- **THEN** 赛事中心显示原名和待补充状态，并使用缺失占位

#### Scenario: 来源时间跨日期
- **WHEN** 来源查询跨越 UTC 日期边界的 36 小时窗口
- **THEN** 在本地精确过滤窗口内的 UTC 开赛时间并显示为 UTC+8

## ADDED Requirements

### Requirement: 按需绑定足球赛果来源
系统 SHALL 在 Polymarket 明确接受足球订单并确认订单身份后启动 API-Football 候选匹配及明确确认；来源不可用或身份不明确 MUST 保持未绑定，不得编造赛果或完赛状态。绑定后按已确认的外部赛事标识核实最终比赛结果。

#### Scenario: 订单结果未知
- **WHEN** 订单提交超时或结果无法确认
- **THEN** 系统先进行只读对账，不启动赛事绑定，也不声称订单成功

#### Scenario: 来源权限不足
- **WHEN** API-Football 套餐无法返回当前赛事
- **THEN** 系统显示来源不可用，保留 Polymarket 赛事和未绑定状态

#### Scenario: 多个候选
- **WHEN** 多场 API-Football 比赛可能匹配
- **THEN** 系统展示候选证据并要求管理员确认，不自动猜测
